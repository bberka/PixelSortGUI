# Drift `v0.3.0` Acceptance Traceability (`T8.11`)

Maps every acceptance criterion of the `v0.3.0` features in [product.md](product.md) to its automated tests: project files (`F25`), full backup and restore (`F17`) and image blending (`F26`). Earlier features stay mapped in [acceptance-v0.1.0.md](acceptance-v0.1.0.md) and [acceptance-v0.2.0.md](acceptance-v0.2.0.md). The other changes listed under `v0.3.0` in `CHANGELOG.md` have their criteria in product.md (`F2`, `F4`, `F12`, `F18`) and tests that name them; they are not repeated here.

Each test is written as its file, then its title in quotes. Titles with `%s` or `%o`, and titles holding a `${...}` value, are table-driven. Tests under `tests/storage/` that name two adapters run against IndexedDB (`fake-indexeddb`) and the in-memory adapter. The `M` numbers point to the [manual checklist](#manual-checklist), which covers what a test machine cannot judge. Run the automated tests with `vp run check` (unit and component), `vp run test:e2e` (Playwright, Chromium and Firefox) and `vp run test:perf` (speed budgets).

## Quota consistency

`tests/storage/quota-consistency.test.ts` runs against IndexedDB (`fake-indexeddb`). For a project file import, a Merge and a Replace backup import, a commit that stores a picked blend image and a project duplicate, it fails the first record written, then the second, and so on to the last. After each failure the library is unchanged, every project lists exactly the images its stacks and history use, each of them is stored, no other image, history entry or thumbnail remains, and the same write then succeeds. It also checks that the three paths that bring in new images refuse one byte below 1.15 times their size and accept at it. Real browser quota behaviour is `M5`.

## imageBlend speed

Targets (engine.md section 9): `settle` at 4 MP, p95 at most 300 ms; `drag`, p95 at most 50 ms. The acceptance limit is `AC-F8.1`: at least 5 updates per second while dragging. Reproduce with:

```sh
RENDER_BENCH=1 pnpm exec playwright test render-bench -g imageBlend --workers=1 --repeat-each=3
```

Result on 2026-11-27, on a machine that was never idle: `settle` p95 misses in both browsers (Chromium 322 to 551 ms, Firefox 346 to 903 ms), `drag` p95 was 26 to 79 ms at a lowered cap, and `AC-F8.1` is met. The `@perf` test of `AC-F26.1` measured 13 to 30 updates per second across four runs in both browsers. All numbers, the load and the recommendation are in [engine.md section 16.5](engine.md#165-multi-image-blending-imageblend-f26). The effect is unchanged in this release.

## Manual checklist

Run against the production build (`vp run gui`) or the published site. A phone needs the published site, because the app needs HTTPS. Record the tester, device, browser version, date and result for each item. None has been run for this document.

| ID | Steps | Pass when |
|---|---|---|
| `M1` | On a real Android phone: add Image blend, pick a camera photo "From device" and another "From library", save a project file, export a backup, open both files again, then open them on a desktop. | Every control can be tapped, the downloads and the file picker work, and both devices show the same picture. |
| `M2` | In Safari on a Mac and on an iPhone: open a `.glproj` and a backup made in Chrome that blend two images, then save both again and open them in Chrome. Safari is best effort. | Record what fails. Nothing existing is lost or changed. |
| `M3` | Disconnect the network after the first visit. With a real 50 MP photo and a 50 MP blend image, save a project file, open it, and export at full size. | Each finishes, the page stays responsive during the save and the open, and the browser tab does not crash. |
| `M4` | Build a library of real photos totalling 2 to 4 GB. Export a backup, import it into a fresh browser profile, then repeat and press Cancel once while packing and once while importing. Try an export over 4 GB. | The backup restores every project. Cancel stops within 1 s and leaves no partial project. The oversized export is refused with the message. Record times and peak memory. |
| `M5` | On a device or profile with little free storage, import a backup and a project file that do not fit, and pick a blend image that does not fit. | "Storage is full" appears, and every existing project still opens and renders. |
| `M6` | On real photos, try every blend mode and fit, with scale, offset and rotation, and compare Multiply, Screen and Overlay with another image editor. | The result looks as the names say, and the preview matches the exported PNG. |
| `M7` | On the reference laptop on mains power, balanced or performance profile, nothing else running, run the speed command above from a normal terminal. | Record median, p95 and load average in this document. |
| `M8` | Open Settings, then About, then View changelog. After the owner publishes the release, check the version and link shown there against the GitHub release. | The `v0.3.0` notes are first and read correctly. |
